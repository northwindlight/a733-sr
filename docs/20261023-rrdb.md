# 2026-10-23：原生两倍 RealESRGAN RRDB

## 行为与边界

高清 MMD 使用轻量 UltraCompact 时会平滑已有发丝和阴影纹理。现改用官方
`RealESRGAN_x2plus`：23 个 RRDB 块、64 特征、16,703,171 参数，原生两倍。
与 General v3 的小型 SRVGG 是不同网络。网页 `rrdb` 默认自动强度 100%，
旧模型和其高清 35% 混合设置保留，后置锐化默认关闭。

同一原片裁图的浮点对照中，RRDB 比 UltraCompact 更清楚地保留发丝和眼睛边缘。
没有真实 4K 参考，不能声称任何视频都会提升。字幕专项暂缓，仍沿用现有底部亮度保护；
本轮主画面达标结论不包括文字重建，后续计划用视觉算法提取字幕再独立处理。
原始整片和旧成品保留，未重跑整条视频。

## 转换和校准

- 输入 352×224，输出 704×448；输入 pixel-unshuffle 与第一层卷积等价合并成
  6×6 / stride 2，避免转换器处理六维 reshape。原始 / 合并网络最大误差约 1.91e-6。
- 本地 ONNX / PyTorch 最大误差约 1.49e-6；真实图块本地 PyTorch / CI ONNX
  最大误差 3.11e-5–5.08e-5，逐值检查通过。
- 发现并修复旧流水线未传量化迭代次数的问题：准备 16 张图时，Pegasus 默认仍只执行
  1 次。现明确 `--batch-size 1 --iterations calib.n`，实际日志确认迭代次数。
- 最终 INT16 / 动态定点使用 DIV2K 32 张图：前 16 张自然图，后 16 张加字幕和细线，
  验证图块未参与校准。禁止随机噪声回退；元数据记录实际迭代、批次和图数。
- INT16 输入是归一化 RGB，新增显式 `--input-int16`。从 NBG 查询 fixed-point
  position，将 `pixel/255` 量化为 INT16；不把原字节直接拷进双字节输入。
  错误类型、形状和非紧密排列输入缓冲区均拒绝。输出使用 SDK 动态定点反量化。

## 分块与速度

重叠 64，core=224×96，1920×1080 共 9×12=108 块。浮点 448×448 裁片与
内部固定图块的对照中，重叠从 16 增到 64 后，边缘两行/列平均差从 0.904 降为
0.468/255，99 分位从 5 降为 3。这只是有限裁片结果，不能称为与整帧网络完全等价。

A733 NPU 1008 MHz、DDR 1800 MHz。单块推理及 SDK 反量化约 1.45 秒，
按 108 块估计，1080p→4K 每帧约 157 秒。原片 6811 帧的纯推理量级约十二天，
不是已跑完整片的测量。设备功耗没有实测，不由吞吐推断能耗比。

## 流水线验证

- `gatetest.py` 通过，Python / JavaScript 语法、shell 语法和 diff 检查通过。
- 新旧输入格式检查与 CPU/GPU/浮点拼帧、带补齐行 NV12、原字幕亮度保护检查通过。
- INT16 路径 `qualitycheck.py`：独立 bicubic 参考误差最多 1/255，BT.601/709 与
  ffmpeg 参考最大差 1/255；CPU/GPU 在 0/35/100% 强度、三组矩阵组合下逐字节一致。
- 网页默认 RRDB、自动 100%、旧模型切换和 JavaScript 错误检查通过。

真实原片的无损裁片经过新模型、GPU 转换和 VE 编码后验证：

两项均为完整模型 100%、不锐化、关闭字幕保护的主画面验证。

成片同位置对照中，发丝和眼睛边缘比旧轻量模型更明确，完整画面未见明显固定接缝。
